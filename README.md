### 把矩形换成三角形，会怎样？

想象一张无限大的方格纸，每个格点涂有一种颜色，总共只用有限种颜色。取一个三角形，把它覆盖的全部格点当作窗口。保持窗口的朝向，在方格纸上平移，每到一处就记下窗口内的配色。假如窗口里有 10 个格点，走遍全平面也只见到至多 10 种配色，本项目的定理就保证：存在一个固定的非零整数位移，让整张图平移后与原图完全重合。

同一个结论适用于任意有限格凸窗口，也就是某个实凸集包含的全部格点。Ho 的定理处理矩形。把三角形补成外接矩形时，新增格点的颜色可能把原本相同的图案区分开，所以三角形上的计数界并不能直接交给矩形定理。

我们把证明过程整理成了一份中英文笔记，仅供大家参考。[proof note（中文）](docs/convex-nivat-zh-notes.pdf) · [proof note（英文）](docs/convex-nivat-en-notes.pdf)

### 推广补了哪一步

Ho 在矩形上的证明给了我们一条路：对整张图做一次沿直线的加权求和，得到一张新图。如果新图在一个更小的窗口上仍然满足“图案数不超过格点数”，就可以按窗口的格点数做归纳。换成三角形以后，首先要弄清楚的就是：这个窗口该怎么缩小？

Ho 的 Lean 工程里已经有一个适用于有限窗口的计数引理。要用上它，我们得证明一件几何上的事：如果一个加权图案经过线滤波后，所有非零项都落在三角形里，那么把滤波器平移到原图案的任一个非零位置，它的所有非零项也都应该落在三角形里。这里的困难是，加权求和会发生正负抵消。单看输出，有些位置可能已经看不见了。[Ho 的有限窗口计数引理](https://github.com/boonsuan/nivat/blob/4e3614024227acd273c3e8ab41df92c2709e5ab0/Nivat/Descent/ExactDescent.lean#L236)

Ho 在矩形证明中用过一个观察：最外端的系数只有一种相乘方式，所以不会抵消。我们把这个观察用到**每一行**。把滤波方向转到水平后，一行最左边的非零项和滤波器最左边的非零项相乘，一定会留下这一行的左端点；右端点也一样。如果这两个端点都在窗口里，格凸性就保证它们之间的每个格点也都在。这就证明了计数引理所需的支撑条件。所有能放下滤波器的位置组成新的窗口。我们证明它仍然格凸；Ho 的计数引理保证它仍满足原来的图案数界，因此非空。再利用滤波器至少有两个非零项，就能证明格点数严格减少。于是归纳可以继续。[Ho 的矩形支撑证明](https://github.com/boonsuan/nivat/blob/4e3614024227acd273c3e8ab41df92c2709e5ab0/Nivat/Algebra/RectangleSupport.lean)

归纳得到的是**滤波后的图有周期**，还要说明原图也有周期。读 Ho 的 Lean 代码时，我们注意到，手稿定理 5.1 虽然对矩形陈述，证明里的一个中间引理已经允许格凸窗口。滤波器的代数性质给出了这个引理所需的混合差分条件。当两个差分方向不平行时，我们改写了 Ho 证明中换坐标的那一步：把原窗口和整张图一起变换，让第一个方向转到水平，就能直接调用他的引理，再把得到的周期带回原坐标。两个方向平行的情形沿用 Ho 已有的论证。[Ho 的格凸窗口引理](https://github.com/boonsuan/nivat/blob/4e3614024227acd273c3e8ab41df92c2709e5ab0/Nivat/TwoFactors/Main.lean#L105)

**这样，矩形就可以换成任意有限格凸窗口，三角形是其中一个例子。** 这个推广也推出了 Colle 预印本第 4 版的猜想 1.11。[Colle 预印本](https://arxiv.org/pdf/1909.08195v4) · [逐项证明与出处](PROVENANCE.zh.md)

## 定理

给定有限字母表，以及整个整数格平面上的一个构型。取有限格点集 D，要求 D 包含其实凸包中的全部格点。如果在 D 的所有整数平移上看到的不同图案数至多为 D 的格点数，那么整个构型有一个非零周期。窗口可以退化成线段上的格点集，也可以只有一个点。空窗口无法满足上述图案数条件。

定理入口是 [ConvexNivat.lean](ConvexNivat.lean) 中的 `Nivat.convex_nivat_real_hull`。命题用 Mathlib 的基本定义写出实凸包、图案集合和周期性结论，无需预先指定方向，也无需假设构型具有回复性。

## 证明用了谁的结果

本项目依赖 [Boon Suan Ho 的仓库](https://github.com/boonsuan/nivat/tree/4e3614024227acd273c3e8ab41df92c2709e5ab0)。Ho 的首页说明了原项目中人和 AI 的分工。

| 步骤 | Ho 已证明的部分 | 本项目在 Lean 中完成的部分 |
|---|---|---|
| 代数准备 | 非零零化子、半平面差分和精确线因子的构造。 | 直接调用上游引理，沿用原假设。 |
| 窗口内的图案计数 | 在乘积支撑满足指定条件时，有限窗口上的秩与纤维计数给出复杂度递降。 | 沿用计数证明，在下一步验证一般格凸窗口也满足它的支撑条件。 |
| 线滤波器的支撑 | 矩形支撑判据、极端系数不抵消的技巧，以及格凸窗口的行区间引理。 | 逐行证明两端不会抵消（`row_endpoint`），由此证明一般格凸窗口的双向支撑判据（`convex_line_fit`）。 |
| 缩小窗口 | 定义滤波器对应的腐蚀窗口，并给出判定格点是否属于它的条件。 | 证明缩小后的窗口仍格凸（`convex_erosion`），并证明当它非空且滤波器至少有两个支撑点时，格点数严格减少（`strict_erosion`）。 |
| 两个因子与周期回传 | 方向对齐后的格凸短窗口引理、平行方向的混合差分引理，以及矩形证明中的坐标变换与周期回传论证。 | 改写坐标变换，把两个方向的情形合并为 `convex_two_factors`，并把滤波后得到的周期性传回原构型。另证整数双分量推论 `convex_two_integer_summands`。 |
| 归纳与最终命题 | 矩形证明的强归纳框架，以及保持图案数和周期的有理数单射编码。 | 按格凸窗口的格点数完成强归纳（`convex_nivat_rational`），再用该编码和实凸包得到任意有限字母表上的 `convex_nivat_real_hull`。 |
| 核对命题与推出 Colle 的猜想 | 提供矩形定理，以及图案数和周期性的定义。 | 用代表起点和固定非零位移独立表述命题，核对矩形与凸窗口版本，再由凸窗口定理推出 Colle 第 4 版猜想 1.11（`order_checked`）。 |

关于两个整数值周期分量的推论，Colle 在[预印本定理 1.12](https://arxiv.org/pdf/1909.08195) 中将它归于 Szabados，另见[正式发表的论文](https://doi.org/10.3934/dcds.2023088)。本项目为所需推论给出了另一条经过 Lean 检查的证明。研究过程中有两条数学线索：经典的 Newton 多面体乘积公式解释了为什么凸性有助于判断乘积支撑是否落在窗口内；Szabados 博士论文中关于平衡条带的论证（引理 6.4.3）处理两个分量之和的周期性。Lean 证明实际使用的是逐行端点论证和一个混合差分引理。本项目导入 Nivat.Main 是为了复用其中的非零性引理。凸窗口定理的证明没有调用矩形情形的最终定理。

## 如何复现

首次解压或克隆项目时，先安装 elan、Git 和 Python 3，确认 `lake` 在 PATH 中，并能联网获取依赖。在仓库根目录的 Bash 中整段运行下面三行即可。前两行准备依赖和缓存，最后一行自动核验本项目的主证明、命题核对、公理和依赖。以后在同一环境只需运行最后一行。

```bash
lake update &&
lake exe cache get $(grep -rh '^import Mathlib' .lake/packages/nivat/Nivat | awk '{print $2}' | sort -u) Mathlib.Data.Real.Basic &&
bash scripts/verify.sh
```

要独立复现上游检查，先获取上游依赖，再**进入上游仓库**运行 `bash scripts/verify.sh --clean`。如果并行内核重放占用内存过多，可以使用下一节的串行脚本。这些脚本使用 Lean 4.33.1 和项目指定的 Mathlib 版本。

本地核验记录放在 [evidence](evidence) 中，其中的上游构建日志是本次重新运行得到的。对本项目新增的每个受检定理，公理检查都会核对它依赖的公理是否在许可清单内。证明重放使用 Lean 自身的内核。由独立实现的检查器复验，以及由人审阅证明，是另外两种检查。

源代码按 [MIT 许可证](LICENSE) 分发。原项目的版权及许可声明也收录在 [LICENSE.upstream](LICENSE.upstream) 中。

## 核验了什么，证明怎样接起来

完整证明已形式化，并通过 Lean 内核检查。论文原文与形式化命题的对应关系见下文“独立核对命题”，供独立复核。

**复核了哪些已有结论？** 主证明从 Ho 的工程调用三组结果：从低图案数构造非零零化子，再由半平面差分得到精确线因子；在支撑条件成立时，用有限窗口计数引理把图案数上界传给滤波后的构型；在两个方向的混合差分为零时，利用方向对齐或平行情形的引理得到周期性。项目重新构建并逐模块重放了固定版本的上游 Lean 证明。逐项出处列出了哪些声明被直接调用、哪些只是改写时的参照。[逐项证明与出处](PROVENANCE.zh.md) · [上游重放记录](evidence/upstream-replay.log)

**推广补了哪些证明？** 设原窗口为 D，线滤波器为 Φ，缩小后的窗口为 S。要把 Ho 的计数引理用在 D 上，必须证明：对任意乘子 g，乘积 gΦ 的支撑落在 D 内，当且仅当 g 的支撑落在 S 内。本项目先证逐行端点不会抵消，再用格凸性证明这个等价关系（`row_endpoint`、`convex_line_fit`）。另外两条引理分别证明 S 仍然格凸，以及在 S 非空且滤波器至少有两个支撑点时，S 的格点数严格小于 D 的格点数（`convex_erosion`、`strict_erosion`）。这些引理都有 Lean 证明。[几何引理](ConvexNivat.lean#L86)

**为什么足以完成归纳？** 在 `convex_nivat_rational` 中，上述支撑等价直接作为参数传入 Ho 的计数引理，得到滤波后构型在 S 上的图案数至多为 |S|。滤波后仍只有有限种取值，因而至少有一种图案，所以上界又保证 S 非空。精确因子消去一个非零差分，这保证滤波器至少有两个支撑点。至此，窗口格凸、格点数严格减少、构型有限值、图案数满足上界，归纳所需的条件全部备齐。归纳先给出**滤波后构型**的周期性；再由 `convex_periodic_of_periodic_line_filter` 推出**原构型**有非零周期。整数双分量推论另有 Lean 证明，主归纳不以该推论为前提。[归纳与周期回传](ConvexNivat.lean#L245)

**怎样检查有没有漏证或换题？** Lean 内核检查整条证明，六个扩展定理入口的公理报告只列出 `propext`、`Classical.choice` 和 `Quot.sound`，没有用来填补未证步骤的 `sorryAx`。依赖检查还确认凸窗口定理没有调用 Ho 的矩形最终定理。至于形式化是否忠实于论文，另需核对定义和量词：后面的“独立核对命题”给出单独写出的目标和连接证明。对 Colle 猜想的最后一步也已形式化：如果这样的构型有非零周期，它自己就是一项周期分解，与最少需要两项矛盾。读者可以分别检查论文表述、独立目标和 Lean 证明。[扩展检查记录](evidence/extension.log) · [独立目标](StatementAudit/Targets.lean) · [连接证明](StatementAudit/Bridge.lean)

## 独立核对命题

[Targets.lean](StatementAudit/Targets.lean) 只导入 Mathlib。它用坐标比较、图案代表位置的有限列表和一个固定的非零位移，独立写出三个命题。凸窗口用实平面凸集与整数格点的交集来定义。图案数的上界允许取等号。有限字母表可以处在任意 Lean 宇宙层级。关于最小分解项数的命题遍历所有整数值周期分量，包括值域无限的分量。

[Rectangle.lean](StatementAudit/Rectangle.lean) 只导入独立写出的目标命题和 Ho 的主模块。它证明，“至多 k 个代表位置就能列全所有图案”等价于 Ho 定义的图案数至多为 k；Ho 定义的周期性也等价于同一对整数组成的固定位移在所有格点上都保持构型不变，且该位移非零。由此得到独立表述的矩形命题。[Bridge.lean](StatementAudit/Bridge.lean) 推出独立表述的凸窗口命题和整数构型最小分解项数命题。后一步用到的理由是：如果构型 c 有周期，那么 c 本身就给出了只有一项的周期分解。

核对量词时对照了 [Kari 和 Szabados 关于 Nivat 猜想的论文](https://arxiv.org/abs/1605.05929)、[Kari 和 Moutot 对格凸形状的定义](https://emoutot.perso.math.cnrs.fr/static/publi/karimoutot20.pdf)，以及 [Colle 预印本第 4 版的猜想 1.11](https://arxiv.org/pdf/1909.08195v4)。该版本中的 1.11 讨论最小分解项数，1.13 讨论非扩张直线，是两个不同的猜想。

上面的核验脚本也可复现这部分检查。它会核对五份新增的公理报告，并分别对三个包含实质证明或命题的审计模块做内核重放。
